## Драматургия

Идём **от частного к общему**:

1. **Конкретная клиническая сцена** — пациент проходит через несколько
   протоколов сразу: информированное согласие → психотерапевтическая сессия →
   включение в исследование. Несколько ролей (пациент, клиницист,
   исследователь, автономный агент, реестр данных).
2. **Платформа** — приложения под каждую роль + Reagent как control plane +
   реестры данных. UI приложений авто-генерируется из протокола.
3. **Живой пример 5.1** — measurement-based терапевтическая сессия с
   safety-границей (PHQ-9/C-SSRS → эскалация), которую можно формально
   верифицировать.
4. **Сертификационный поворот** — главный коммерческий тезис: сертифицируем
   платформу один раз → протоколы валидируются по отдельности как
   конфигурация, а не как новый софт.
4a. **Второй кейс — межорганизационный обмен данными** (data space): частная
   модель пациента из фрагментов у разных компаний; консент + гейт держателя +
   анонимизация на источнике; verify-инварианты «нет данных без согласия / нет
   egress без анонимизации». Показывает кросс-орг измерение и усиливает P4.
5. **Обобщение** — то, что мы видели в клинике, это частный случай. Reagent —
   это язык и рантайм для описания **взаимодействий**, а не свойств агентов.
6. **Видение** — кибер-физический рынок из людей и агентов; безопасность через
   описание сети взаимодействий, а не через изоляцию отдельных агентов.

## Ключевые тезисы

- В мире, который наполняется автономными агентами, узкое место — не
  интеллект, а **управляемость, предсказуемость, аудируемость**.
- Reagent делает **взаимодействие** первоклассным объектом: протокол — это
  исполняемый артефакт (как реакция в химии), а не код, спрятанный в промптах.
- Клиника — идеальная вертикаль: здесь protocol-first + verification + audit
  не «приятно», а **обязательно**.
- **Executable protocol = executable RFC**: спецификация и runtime — один файл.
- **Модульная сертификация** — платформа сертифицирована, протокол
  валидируется отдельно (опора на GAMP 5, FDA PCCP, IEC 62304, 21 CFR Part 11,
  ICH GCP). Это снижает стоимость и время вывода каждого нового протокола.
- Авто-генерируемый UI замыкает сертификацию на фронтенд (UI — проекция
  протокола, не отдельный custom-код).
- **Соглашение об обмене данными — исполняемый контракт.** В data space
  (несколько компаний, EHDS/Gaia-X) консент, минимизация и анонимизация —
  это шаги верифицируемого `.rg`, а не политика, зашитая в коннектор.
- Reagent — control plane: RC исполняет state machine, protocol-bounded
  interaction, гетерогенные агенты, распределённость, verify, OTel.
- Парадигма: **описываем взаимодействия, которые хотим видеть в сети**,
  безопасность by construction, а не sandboxing/фильтры поверх автономии.

## Честные оговорки (для экспертов)

- Модульная сертификация — продуктовая гипотеза, требует диалога с регулятором.
- LLM-недетерминизм остаётся отдельным регуляторным объектом.
- Авто-UI и часть рантайм-надёжности (durable execution на уровне шагов) —
  roadmap, а не готовое.
- Дека сознательно описывает язык/рантайм **безотносительно текущего стейта**
  PoC — это видение архитектуры, а не статус реализации.
